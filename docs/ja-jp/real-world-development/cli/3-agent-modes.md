プロジェクトに小さな機能を追加しました。大きな変更には、よりしっかりしたプロセスが必要です。GitHub Copilot CLI は、組織の既存の開発フローに沿って、適切な方法で必要なものを作成できるように設計されています。このレッスンから始まる一連の演習では、Issue から新機能を作り、コードが有効で機能が想定どおりに動作することを確認して、最終的にプロジェクトにマージするという、一般的なエージェント主導の開発プロセスに沿って進めます。

> [!NOTE]
> 機能のワークフローを続ける間は、同じ会話とブランチを使用します。通常は作業するファイルの種類ごとに別のブランチや PR を使いますが、ここでは主要な概念に集中できるよう手順を簡略化しています。

このレッスンでは、次のことを行います。

- GitHub Issue から Copilot の新しい会話を始めます。
- Plan モードで要件を定義します。
- Autopilot モードで新機能を実装します。
- コードをレビューします。
- 転送されたブラウザーで機能を手動で検証します。

この機能の作業を続けながら、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して、QA エージェントを作成し、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログは増え続けており、訪問者はカテゴリと発行元でゲームを絞り込む必要があります。バックログの Issue に機能の説明がありますが、カテゴリの組み合わせなど、コーディング前に決めることが残っています。Plan モードでこれらを決定し、範囲を限定した実装を Autopilot に依頼します。

## 背景

AI コーディング エージェントを開発フローに導入しても、基本は変わりません。むしろ、より重要になります。多くの開発者は次のような流れで作業します。

1. 実施内容を説明する Issue から始めます。
2. 作成するものの計画を立てます。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新しい機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードのレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> チームや組織によって詳細は異なりますが、ほとんどの場合、上記の流れに沿って作業します。

この標準的な方法に従うことで、AI が生成したコードが要件を満たし、手動で書いたコードと同じレビューを受けられます。

## 会話モード

**会話モード**は、エージェントにどの程度の自律性を与えるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すとモードを切り替えられます。

- **Interactive**: エージェントが変更を提案し、続行前にユーザーの入力を待ちます。
- **Plan**: エージェントが最初に計画を作成します。プロジェクト ファイルの編集は行いません。
- **Autopilot**: エージェントが自律的に作業し、コードの作成、テスト、反復を行ってタスクを完了します。

最初に Plan モードで計画を確認し、その後 Autopilot に実装を依頼します。

## Issue から始める

フィルタリング作業を始める前に、Codespace に戻り、リポジトリとターミナルが準備できていることを確認します。

1. Codespace に戻ります。停止している場合は、再開してから続けます。
2. 星評価の PR がマージされていることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、フィルタリング作業用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押して、すべての Issue を表示します。
8. 矢印キーで **Allow users to filter games by category and publisher** というタイトルの Issue を選択します。
9. <kbd>C</kbd> を押して Issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトの先頭に `#7` (または同様の番号) が表示されます。`#` を使うと、GitHub 上の Issue またはプルリクエスト (PR) をコンテキストに含めることができます。

## フィルタリング機能を計画する

計画を立てると、Copilot に実装を依頼する前に、機能の作成方法やタスクの進め方を定義できます。複雑な作業では、事前に時間をかけて計画を立てることをお勧めします。Plan モードに切り替えて、計画を作成するよう Copilot に依頼します。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** であることを確認します。
2. 前の手順で追加した Issue の後に、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot はプロジェクトを調べ、最適な方法を検討して計画を作成します。

3. フィルタリング機能の動作について、Copilot から質問される場合があります。希望に沿って回答してください。正解は 1 つではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して展開します。
5. 上下にスクロールして計画をレビューします。
6. 計画が決定と一致しない場合は、該当箇所を修正するよう Copilot に依頼します。

## Autopilot を承認する

計画を作成してレビューしたので、実装を始めます。Autopilot を使い、Copilot に作業を任せましょう。

Autopilot を使うと、Copilot は問題が完了したと判断するまで反復して作業します。

1. **Accept plan and build on autopilot (recommended)** または、インストール済みのバージョンに表示される同様のオプションを選択します。
2. プロンプトの下にあるモード表示が **Autopilot** であることを確認します。
3. Copilot が計画に沿ってコードを作成し、テストを実行して反復する様子を確認します。

> [!NOTE]
> 承認すると、すぐに実装が始まる場合があります。最初に計画をレビューしてください。依存関係がない、またはポートが競合していると Copilot が報告した場合は、チェックが完了したと判断する前にセットアップの問題を解決します。

## 実装をレビューして検証する

ほかのコードと同様、生成されたコードもマージする前にレビューします。コードを確認し、サイトを実行して問題がないことを確かめます。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示が **Plan** または **Autopilot** ではないことを確認します。
2. `/diff` を入力し、フィルタリングの実装とテストを確認します。
3. 結果を Issue と計画時に決めた内容と比較します。
4. コードのレビューが終わったら <kbd>Esc</kbd> を押して差分ビューを閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に修正を依頼します。

## 新しい機能を確認する

コードに問題がなさそうでも、実際に動くでしょうか。前と同じようにアプリを起動し、Codespaces の転送ポートからサイトを開きます。

1. Copilot にアプリの起動を依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces でポート `4321` が利用可能と表示されたら **Open in Browser** を選択します。
3. 計画で決めたカテゴリのフィルター、発行元のフィルター、それらの組み合わせを試します。
4. リセットや結果が空の場合の動作が、Issue と決定内容に合っていることを確認します。
5. Codespace に戻り、起動した開発サーバーを停止するよう Copilot に依頼します。

## まとめと次のステップ

会話モードを切り替えて機能を作成し、レビューしました。このレッスンでは、次のことを行いました。

- GitHub Issue から Copilot の新しい会話を始めました。
- Plan モードで要件を定義しました。
- Autopilot モードで新機能を実装しました。
- コードをレビューしました。
- 転送されたブラウザーで機能を手動で検証しました。
