GitHub Copilot をエージェント モードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。Copilot はローカル マシンでリアルタイムに作業するため、VS Code の Copilot Chat ではツール呼び出しやファイル編集の状況を確認できます。差分をインラインでレビューし、個々の変更を受け入れるか取り消すことができます。また、エディターを離れずに追加のプロンプトを送信し、作業を改善したり拡張したりできます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして受け入れます。
- セッションの途中でエージェントに指示し、ハイ コントラスト モードに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使用したアクセシビリティのカスタム エージェントが、ハイ コントラスト モードを実装しています。作業中にデザイン チームから追加の依頼がありました。既定のテーマを暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加してほしいとのことです。会話を最初からやり直すのではなく、進行中のセッションに指示を追加します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが行う各手順が表示されます。調べたファイル、実行したコマンド、提案した編集を確認できます。ファイルを編集すると、差分と **Keep** / **Undo** の操作がインラインで表示されます。

1. 演習 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
    - 変更を受け入れるには **Keep** を選択します。
    - 変更を取り消し、エージェントに再度対応してもらうには **Undo** を選択します。
4. チャットの上部にある **Files changed** を開くと、このセッション中にエージェントが変更したファイルをすべて確認できます。

> [!NOTE]
> ターミナル コマンドの実行などでツールの使用許可を求められると、エージェントは処理を一時停止して **Allow** を表示します。内容を確認し、許可するコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を完了するまで待ちます。変更の概要を示す最終メッセージが表示されます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。チャット セッションを続けるため、エージェントは前の作業から、変更したコンポーネント、スタイルの方針、設定した local storage のパターンなどのコンテキストを保持しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前回の変更を調べ、ライト モードの追加を提案します。
3. ハイ コントラスト モードのときと同じように、新しい編集を確認します。各差分で **Keep** または **Undo** を選択します。
4. エージェントが意図しない方向に進んだ場合 (たとえば、好みでない方法で切り替え UI をリファクタリングしようとする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、明確にするための追加メッセージを送信できます。

> [!TIP]
> 進行中のセッションに指示を追加すると、最初からやり直すよりも速く作業できます。「CSS を簡素化し、セレクターを重複させず CSS 変数を使ってください」のように調整を依頼したり、「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを追加してください」のように方針を修正したり、「両方の切り替えにキーボード ショートカットも追加してください」のように範囲を広げたりできます。

## 作業内容をレビューする

コミットする前に、エージェントが変更したすべての内容を簡単に確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連するテストなどが更新されているはずです。
3. 変更されたファイルをいくつか開いて差分を確認します。カスタム エージェントが指示したアクセシビリティ パターン、ARIA 属性、キーボード ナビゲーション、セマンティック HTML、local storage による設定保存が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードで進行中のセッションを監視し、ファイル編集ごとに確認して、変更を受け入れるか取り消しました。また、コンテキストを保ったまま追加のプロンプトを送信し、作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を受け入れたり、取り消したりしました。
- 追加のプロンプトを使って進行中のセッションに指示を追加しました。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボを通じてローカルのカスタム エージェントが作成した変更をレビューします。
